MediaVault

Video asset management SaaS for creative teams. Built as a production-style portfolio project emphasizing relational design, authorization, and search.

GitHub repository View architecture

Problem

Teams accumulate media quickly. Without workspaces, folders, tags, and permissions, assets become unsearchable and unsafe to share.

Solution

Versioned FastAPI (/api/v1) with JWT auth, workspace membership roles (ADMIN / MEMBER / VIEWER), folder trees, tagged assets, full-text search, pagination, and signed download URLs—backed by a React DAM-style UI.

Architecture

React SPA → FastAPI /api/v1 (auth, workspaces, assets, folders, tags, search, shares) → PostgreSQL (indexes + FTS) → Object storage abstraction (local / S3) + signed URLs

Key features

  • Workspaces and membership RBAC
  • Asset upload, folders, tags
  • Search, filter, sort, pagination
  • Share links and permission checks
  • Grid/table library UX, upload modal, user management

Technical decisions

  • Explicit API versioning for stable contracts
  • Authorization checked at workspace and asset boundaries
  • Database indexes and FTS chosen for library query patterns
  • Signed URLs instead of forever-public object paths

Challenges

  • Keeping RBAC consistent across list/detail/share endpoints
  • Folder navigation UX that still maps cleanly to relational data
  • Upload safety without blocking legitimate large media

Testing

API tests for auth, RBAC, search, and pagination; frontend smoke tests; CI lint/test/build.

Infrastructure

Docker Compose locally. Documented AWS: S3 + CloudFront signed URLs, RDS PostgreSQL, ECS API.

What I learned

Asset products are permission products. Clean schema and index choices matter as much as UI polish when libraries grow.
