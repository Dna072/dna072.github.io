StreamPulse

Video analytics and performance dashboard. Built as a production-style portfolio project where charts are powered by real backend aggregations—not hardcoded frontend series.

GitHub repository View architecture

Problem

Product and content teams need trustworthy views of watch time, completion, audience, and device/geo mix—with filters and comparison periods that stay responsive.

Solution

FastAPI metrics endpoints over PostgreSQL event data, seeded with realistic demo history. React dashboard renders KPIs, time series, funnels, and breakdowns from those APIs, with loading/error/empty states.

Architecture

Seeded events (views, progress, geo, device) → PostgreSQL + indexes → FastAPI aggregations (overview, timeseries, video, audience, geo, device) → React dashboard (Recharts) with date/video filters

Key features

  • Overview KPIs and time series
  • Top videos, engagement funnel
  • Geographic and device analytics
  • Date range + video filters; comparison mode
  • Documented indexes and query rationale

Technical decisions

  • Push aggregation to SQL where the database is strongest
  • Index for time-range and video-scoped queries
  • Frontend never fabricates metric series

Challenges

  • Seed data volume vs. local Docker performance
  • Consistent empty/error states when filters yield no rows
  • Comparison periods without duplicative query logic

Testing

API tests for aggregations and filters; frontend tests for dashboard states; CI pipeline.

Infrastructure

Compose locally. AWS sketch: RDS, ECS API, CloudFront UI; optional read replica later.

What I learned

Analytics UX quality tracks query design. Indexes and honest loading states beat decorative charts with fake numbers.
