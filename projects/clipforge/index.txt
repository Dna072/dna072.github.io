22:T62d2,<h1>ClipForge — AI Video Processing &#x26; Content Intelligence Platform</h1>
<blockquote>
<p><strong>Built as a production-style portfolio project</strong> by Derrick Adjei.
Not a live commercial product — there are no real users, revenue, or uptime
claims. Every number in this README is either a configuration value or a local
test result.</p>
</blockquote>
<p>ClipForge is a media SaaS backend (with a polished React dashboard) that ingests
videos and turns them into structured content intelligence: extracted technical
metadata, thumbnails, an audio track, a transcript, and AI‑generated summary,
chapters, and tags. Processing happens <strong>asynchronously</strong> through a Redis‑backed
worker so the API stays responsive under load.</p>
<p>It runs <strong>fully offline in demo mode</strong> — the <code>MockAIProvider</code> produces realistic,
deterministic AI output with no API key or network access, so the entire
<code>upload → queue → process → AI results</code> path works out of the box.</p>

<h2>Architecture</h2>
<p>ClipForge separates the <strong>synchronous request path</strong> (auth, uploads, reads) from
the <strong>asynchronous processing path</strong> (the heavy media/AI work), connected by a
Redis queue.</p>
<pre><code class="language-mermaid">flowchart LR
    subgraph Client
      FE["React + TS SPA&#x3C;br/>(nginx)"]
    end

    subgraph API["FastAPI API"]
      R["Routers&#x3C;br/>/api/v1/*"]
      SVC["Services&#x3C;br/>(business logic)"]
      REPO["Repositories"]
    end

    Q[("Redis&#x3C;br/>job queue")]
    W["Worker&#x3C;br/>(pipeline consumer)"]
    DB[("PostgreSQL")]
    ST[["Object storage&#x3C;br/>(local FS / S3)"]]
    AI{{"AIProvider&#x3C;br/>Mock | OpenAI"}}

    FE -->|HTTPS /api| R --> SVC --> REPO --> DB
    SVC -->|save upload| ST
    SVC -->|enqueue job| Q
    Q -->|dequeue| W
    W -->|ffprobe / ffmpeg| ST
    W --> AI
    W -->|update video + job| DB
    FE -->|poll status| R
</code></pre>
<p><strong>Clean architecture, inward dependencies only:</strong></p>
<pre><code>api  ->  services  ->  repositories  ->  models
                \->  ai (protocol)   \->  (SQLAlchemy)
</code></pre>
<ul>
<li><strong>Routers</strong> (<code>app/api</code>) — HTTP concerns only: parse/validate, call a service,
serialize a schema.</li>
<li><strong>Services</strong> (<code>app/services</code>) — business logic and orchestration; framework‑
agnostic and unit‑testable.</li>
<li><strong>Repositories</strong> (<code>app/repositories</code>) — all query/ORM logic, keeping SQL out of
services.</li>
<li><strong>AI abstraction</strong> (<code>app/services/ai</code>) — a <code>Protocol</code> the pipeline depends on;
concrete providers are swapped by a factory.</li>
<li><strong>Worker</strong> (<code>app/workers</code>) — a standalone process running the same
<code>ProcessingPipeline</code> used in tests.</li>
</ul>
<h3>Processing pipeline (per video)</h3>
<pre><code class="language-mermaid">sequenceDiagram
    participant U as User
    participant API
    participant Q as Redis
    participant W as Worker
    participant AI as AIProvider
    U->>API: POST /videos (multipart upload)
    API->>API: validate (type/size/ext/MIME)
    API-->>U: 201 {status: queued}
    API->>Q: enqueue {job_id, video_id}
    W->>Q: BRPOP job
    W->>W: 1. ffprobe metadata
    W->>W: 2. ffmpeg thumbnail (non-fatal)
    W->>W: 3. ffmpeg audio extract (non-fatal)
    W->>AI: 4. transcribe(audio)
    W->>AI: 5. analyze(transcript) -> summary/chapters/tags
    W->>API: video.status = completed (persisted to DB)
    U->>API: GET /videos/{id}/status (poll)
</code></pre>
<p>Each stage records its own status on the job (<code>steps</code>) so the UI renders a live
checklist. Thumbnail/audio failures are <strong>non‑fatal</strong> — a single undecodable file
never blocks AI insights, and the pipeline degrades gracefully when ffmpeg is
absent.</p>

<h2>Features</h2>
<ul>
<li><strong>JWT auth</strong> — register/login with access + refresh tokens; transparent token
refresh on the client; bcrypt hashing.</li>
<li><strong>Workspaces &#x26; projects</strong> — every user gets a default workspace on signup;
membership‑scoped authorization on all reads/writes.</li>
<li><strong>Validated uploads</strong> — extension, MIME type, size, and empty‑file checks, with
defence‑in‑depth re‑validation against bytes actually written.</li>
<li><strong>Async processing pipeline</strong> — metadata (ffprobe), thumbnail + audio (ffmpeg),
transcript, and AI summary/chapters/tags, dispatched via Redis.</li>
<li><strong>AI provider abstraction</strong> — real OpenAI or fully offline mock (demo mode).</li>
<li><strong>Search &#x26; filtering</strong> — search across title/summary/transcript, filter by
status/project, paginated.</li>
<li><strong>Dashboard stats</strong> — totals, duration, storage, status breakdown, recents.</li>
<li><strong>Live status</strong> — job step checklist with client polling until completion.</li>
<li><strong>Operational endpoints</strong> — OpenAPI docs, <code>/health</code>, <code>/ready</code>, structured logs,
request IDs, consistent error envelope.</li>
<li><strong>Polished dark UI</strong> — responsive SaaS media‑tool look (charcoal/slate + amber),
with loading/error/empty states throughout.</li>
</ul>

<h2>AI provider abstraction</h2>
<p>The pipeline depends only on a <code>Protocol</code>, never on a vendor SDK:</p>
<pre><code class="language-python">class AIProvider(Protocol):
    name: str
    def transcribe(self, audio_path: str, *, duration_seconds: float | None = None) -> Transcript: ...
    def analyze(self, transcript: str, *, title: str, duration_seconds: float | None = None) -> ContentInsights: ...
</code></pre>
<ul>
<li><strong><code>MockAIProvider</code></strong> — deterministic, offline. Powers demo mode and tests.</li>
<li><strong><code>OpenAIProvider</code></strong> — Whisper transcription + a JSON‑constrained chat model for
summary/chapters/tags, wrapped in retries.</li>
<li><strong><code>get_ai_provider()</code></strong> — a factory that selects OpenAI only when a key is
configured and <strong>falls back to mock</strong> otherwise, so the AI path never breaks.</li>
</ul>
<p>This makes the interesting business logic (the pipeline) testable without network
access, and makes swapping AI vendors a one‑line change.</p>

<h2>Engineering decisions</h2>
<ul>
<li><strong>Queue over background tasks.</strong> Media/AI work is offloaded to a dedicated
worker via Redis so the API never blocks on ffmpeg or model latency, and
workers scale independently of the API.</li>
<li><strong>Provider abstraction for AI.</strong> Depending on a <code>Protocol</code> (not the OpenAI SDK)
keeps the pipeline unit‑testable and vendor‑swappable, and enables a genuinely
functional offline demo instead of stubbed 501s.</li>
<li><strong>Clean layering.</strong> Routers → services → repositories → models keeps SQL out of
business logic and business logic out of HTTP handlers, so each layer is tested
in isolation.</li>
<li><strong>Graceful degradation.</strong> ffmpeg/ffprobe missing or a bad file? Those steps are
marked <code>skipped</code>/<code>failed</code> and the pipeline continues. Redis down? The API falls
back to an in‑memory queue so reads/writes keep working.</li>
<li><strong>Membership‑scoped queries.</strong> Authorization is enforced at the repository layer
(every video query joins through workspace membership), preventing horizontal
access bugs.</li>
<li><strong>Config as env.</strong> One image, many environments; secrets never live in code.</li>
<li><strong>Portable persistence.</strong> A <code>JSONType</code> renders <code>JSONB</code> on Postgres and <code>JSON</code> on
SQLite, so the same models power fast in‑memory tests and production.</li>
</ul>

<h2>Future improvements</h2>
<ul>
<li><strong>SQS + DLQ</strong> instead of a Redis list for managed retries, visibility timeouts,
and dead‑letter handling; idempotency keys per job.</li>
<li><strong>WebSocket/SSE</strong> push for live status instead of client polling.</li>
<li><strong>Real streaming playback</strong> (HLS/DASH transcode ladder) and signed URL delivery.</li>
<li><strong>Semantic search</strong> over transcripts using embeddings + pgvector.</li>
<li><strong>Role‑based access control</strong> and workspace invitations (schema already supports
member roles).</li>
<li><strong>Chunked/resumable uploads</strong> (tus / S3 multipart) for large files.</li>
<li><strong>Per‑workspace usage quotas</strong> and rate limits backed by Redis.</li>
<li><strong>Observability</strong>: OpenTelemetry traces spanning API → queue → worker.</li>
</ul>
