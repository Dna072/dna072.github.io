17:T11fd,<h1>JobPilot</h1>
<p>Autonomous <strong>career-engineering</strong> system for Derrick Adjei: discover European jobs (Sweden first), score them honestly, close portfolio gaps, tailor one of three LaTeX resumes, and apply only through legitimate channels.</p>
<p>This is not a spray-and-pray auto-apply bot. It maximizes <em>quality-adjusted</em> applications and <strong>never</strong> marks an application <code>SUBMITTED</code> without confirmation evidence.</p>
<h2>What discovery found</h2>
<p>The <code>jobpilot</code> workspace started empty. Candidate evidence was loaded from:</p>
<ul>
<li>Existing PDF resume (<code>cv/source/Derrick_Adjei_Resume.pdf</code>)</li>
<li>GitHub <a href="https://github.com/Dna072"><code>Dna072</code></a></li>
<li>Portfolio site <a href="https://dna072.github.io"><code>dna072.github.io</code></a></li>
</ul>
<p>The three LaTeX masters did <strong>not</strong> exist; they were created from that evidence under <code>cv/</code> and must not be overwritten by tailoring.</p>
<p>Full write-up: <a href="docs/candidate-profile.md"><code>docs/candidate-profile.md</code></a>.</p>
<h2>Architecture</h2>
<pre><code>Job Scout → Analyst → Match → Gap / Project → CV select &#x26; tailor → Apply
                                                              ↘ Human action email
</code></pre>
<p>Agents speak <strong>Pydantic schemas</strong>, not chat. LLM providers are swappable (<code>LLM_PROVIDER=heuristic|openai</code>). The heuristic provider keeps tests and offline use deterministic.</p>
<h2>Quick start</h2>
<pre><code class="language-bash">python -m venv .venv &#x26;&#x26; source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
jobpilot init-db
jobpilot seed
jobpilot status
pytest -q
</code></pre>
<p>Run the control plane:</p>
<pre><code class="language-bash">jobpilot serve          # FastAPI on :8000
cd frontend &#x26;&#x26; npm install &#x26;&#x26; npm run dev
</code></pre>
<p>Or: <code>docker compose up --build</code> (Postgres, Redis, API, worker, beat, web).</p>
<h2>CLI</h2>
<pre><code class="language-bash">jobpilot status          # pipeline counters
jobpilot scout           # permitted job feeds only
jobpilot cycle           # scout + process
jobpilot cycle --no-scout
jobpilot watch-repos     # detect human-created GitHub repos
jobpilot report          # weekly performance email
</code></pre>
<h2>Applying</h2>
<p>Live HTTP apply is <strong>off</strong> until you set:</p>
<pre><code class="language-text">JOBPILOT_ALLOW_LIVE_APPLY=true
</code></pre>
<p>and <code>applications.dry_run: false</code> in <code>config/jobpilot.yaml</code>.</p>
<p>Even then JobPilot will <strong>not</strong>:</p>
<ul>
<li>bypass CAPTCHA or bot detection</li>
<li>automate LinkedIn</li>
<li>steal cookies or rotate identities</li>
<li>reverse-engineer private ATS APIs</li>
<li>claim success without a confirmation id / page / ATS status</li>
</ul>
<p>If a human step is required you get:</p>
<pre><code class="language-text">ACTION REQUIRED — [COMPANY] — [ROLE]
</code></pre>
<p>with the tailored CV, cover letter, and screening answers attached in the package.</p>
<h2>New repositories</h2>
<p>Cursor cannot create GitHub repositories. If a streaming/Kafka (or other) project is justified, JobPilot emails:</p>
<pre><code class="language-text">ACTION REQUIRED — Create Repository: [PROJECT]
</code></pre>
<p>and sets <code>PROJECT_STATUS = WAITING_FOR_REPOSITORY</code> until the repo appears.</p>
<h2>GCP (always-on)</h2>
<p>A laptop is enough for <code>jobpilot cycle</code>. Continuous scout / repo-watch / weekly email needs a host.</p>
<p>GCP config lives in <a href="infra/gcp"><code>infra/gcp</code></a> and is documented in <a href="docs/gcp.md"><code>docs/gcp.md</code></a>:</p>
<pre><code class="language-bash">export GCP_PROJECT=your-project-id
./scripts/gcp-deploy.sh
</code></pre>
<p>That provisions Cloud Run (API + dashboard), Cloud SQL, Cloud Scheduler jobs, Secret Manager, and a GCS bucket for generated CVs. Redis/Celery are not used in GCP — Scheduler runs <code>jobpilot cycle</code> every six hours.</p>
<h2>Configuration</h2>
<p>All targeting, weights, and caps live in <a href="config/jobpilot.yaml"><code>config/jobpilot.yaml</code></a>. Do not hard-code them.</p>
<h2>Honesty rules</h2>
<ul>
<li>Portfolio repos are never rewritten as KPMG/NTC employment.</li>
<li>NexDev / SIMSGH / MedLink / Arctiq are product work without a fabricated job title.</li>
<li>NTC titles/dates differ across resume, LinkedIn, and the candidate brief; all variants are stored, not blended into a new title.</li>
</ul>
