21:T3fa7,<h1>MediaVault — Video Asset Management for Creative Teams</h1>
<p>MediaVault is a media library / digital-asset-management (DAM) platform aimed at
video-first creative teams. It focuses on the backend and data engineering that
production media tooling actually requires: multi-tenant workspaces, role-based
access control, a folder hierarchy, tagging, PostgreSQL full-text search, and
tamper-proof <strong>signed URLs</strong> for secure asset delivery — fronted by a polished
React + TypeScript single-page app.</p>
<blockquote>
<p><strong>Portfolio note.</strong> This is a production-style portfolio project built by
Derrick Adjei. It ships with realistic seed data but <strong>no real customers,
revenue, or uptime claims</strong>. Benchmarks (if any) are test results only.</p>
</blockquote>

<li>JWT authentication with <strong>access + refresh token rotation</strong> and server-side
revocation (logout, reuse detection).</li>
<li><strong>RBAC</strong> with three workspace-scoped roles — <code>ADMIN</code>, <code>MEMBER</code>, <code>VIEWER</code> —
enforced centrally.</li>
<li>Multi-tenant <strong>workspaces</strong> with membership management.</li>
<li><strong>Folder hierarchy</strong> (materialized paths) with move/rename that re-paths
descendants, breadcrumbs, and subtree queries.</li>
<li><strong>Tags</strong> and asset tagging with AND-filtering.</li>
<li><strong>PostgreSQL full-text search</strong> (weighted <code>tsvector</code>, GIN index, trigger) with
a graceful <code>ILIKE</code> fallback on SQLite for tests.</li>
<li><strong>Pagination, filtering and sorting</strong> on all list endpoints.</li>
<li><strong>Signed URL</strong> generation for asset access (HMAC, expiring) — with a native S3
presigned-URL path when the S3 backend is enabled.</li>
<li>Pluggable <strong>storage abstraction</strong> (local disk or S3/MinIO).</li>
<li><strong>Upload validation</strong>: content-type allow-list, size limits, and magic-number
sniffing to catch spoofed content types; SHA-256 checksums.</li>
<li>Public, revocable, <strong>download-limited share links</strong>.</li>
<li>Health (<code>/health</code>) and readiness (<code>/ready</code>) probes.</li>
<li><strong>Structured JSON logging</strong> with per-request IDs (<code>X-Request-ID</code>).</li>
<li>Clean layering: <code>api / core / models / schemas / services / repositories / utils</code>.</li>
</ul>
<p><strong>Frontend (React + TypeScript + Vite)</strong></p>
<ul>
<li>Polished DAM UI (slate + teal, light/soft-dark themes) — not a Bootstrap CRUD.</li>
<li>Sidebar navigation, workspace switcher, and folder tree.</li>
<li>Asset <strong>grid and table</strong> views with sorting.</li>
<li>Full-text <strong>search + type/tag filters</strong>.</li>
<li><strong>Upload modal</strong> with drag-and-drop and multi-file support.</li>
<li>Asset <strong>detail drawer</strong> with preview, tagging, share links and delete.</li>
<li><strong>People &#x26; permissions</strong> management and tag administration.</li>
<li>Complete auth flow and first-class loading / error / empty states.</li>
</ul>

<h2>Authentication &#x26; RBAC</h2>
<ul>
<li>Passwords are hashed with bcrypt.</li>
<li>Login issues a short-lived <strong>access</strong> token and a longer-lived <strong>refresh</strong>

(presenting a used token is rejected — basic reuse detection).</li>

role. Handlers call <code>ctx.require(Role.MEMBER)</code> / <code>require_admin()</code>:</li>

<h2>Signed URLs &#x26; storage</h2>
<p>Assets are never served from a public bucket path. A download URL is minted on
request and carries an HMAC signature over <code>asset_id</code> + expiry:</p>
<pre><code>/api/v1/assets/{id}/download?expires=&#x3C;ts>&#x26;signature=&#x3C;hmac>
</code></pre>
<p>The download endpoint verifies the signature and expiry before streaming bytes —
the same model as S3 / CloudFront signed URLs. When <code>STORAGE_BACKEND=s3</code>, the
service instead returns a native S3 presigned URL so bytes are served directly
from object storage. The <code>StorageBackend</code> abstraction (<code>app/services/storage.py</code>)
keeps call sites identical across local disk and S3/MinIO.</p>
<hr>
<h2>Search</h2>
<p>On PostgreSQL, asset name/description/filename are indexed into a weighted
<code>tsvector</code> (<code>A</code>/<code>B</code>/<code>C</code>) maintained by a trigger, queried with
<code>websearch_to_tsquery</code> and ranked with <code>ts_rank</code>, accelerated by a GIN index.
On SQLite (used in tests) the repository transparently falls back to <code>ILIKE</code>
matching, so the same code path is exercised end-to-end without Postgres.</p>
